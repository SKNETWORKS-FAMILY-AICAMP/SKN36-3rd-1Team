# Checker 연계 LLM 3종 비교 (#82)

PR #56의 Generator 단독 평가(`policy_checks=[]`)를 보완해, 같은 5개 실제 질문
(RQ027/031/036/040/042)을 **실제 검색 → 실제 Checker(check_eligibility) → 실제 Generator**로
이어지는 `run_ask_pipeline` end-to-end 경로로 다시 돌렸다. 모델은 PR #56과 동일하게
GPT-5.4-nano/mini/5.4 3종, 질문당 프로필은 입력 없음(age/income=None, region="")으로
고정했다. 질문 은행에 프로필이 없어 정보 미입력 시나리오로 평가했다.

실행: `tests/evaluation/llm_comparison/compare_checker_integrated.py --execute --budget 0.30`
(`.venv/Scripts/python.exe`, 레포 루트에서 실행)

## 결과 요약

- 15/15 호출 성공, `ask_error` 없음, 인용 형식은 `run_ask_pipeline`의 `_citations()`가
  자체 검증하므로(실패 시 `AskError` 발생) 전부 통과한 셈이다.
- 총 비용 **$0.083581** (예산 $0.30 중). 모델별 합계: nano $0.0037 / mini $0.0164 / 5.4 $0.0638.
- `num_needs_check_conditions`로 Checker가 실제로 개입했는지 확인됨 — RQ040(POL_005, 국민내일배움카드)은
  조건 16개가 모두 `needs_check`로 보류돼, 이 정책의 그래프 데이터 품질 경고가 이번 평가에서도
  그대로 재현됐다(별도 데이터 이슈, 이 비교 자체의 결함 아님).

## PR #56 대비 달라진 점

PR #56 보고서는 GPT-5.4-mini에서 RQ040 긍정/부정 표현 오류, RQ042 핵심 조건 누락을 지적했다.
저장된 응답과 질문 은행의 근거 문구를 다시 대조한 결과는 다음과 같다.
아래 의미 평가는 질문의 핵심 답변과 표현을 대상으로 한 수동 재검토다.
인용 형식 통과는 정책 사실 전체의 정확성을 보장하지 않으며, 부가 설명의 전수 원문 검수는 남아 있다.

PR #56에서 지적한 mini의 RQ040 긍정/부정 표현 혼동은 이번 기록에도 남아 있다.
mini의 RQ042에는 해당 제외 조건이 포함돼 있어, 이번 저장 응답에서는 핵심 누락이 관찰되지 않았다.
nano의 RQ042에는 별도의 결론 명확성 문제가 있다.

이 과거 실행에는 생성 입력과 모델 원본 출력이 저장되지 않았다.
따라서 차이가 Checker, 검색 근거, 후처리 중 어느 요소에서 비롯됐는지는 확정할 수 없다.
평가 문항도 5개뿐이므로 운영 모델의 일반적인 품질로 확대 해석하지 않는다.

## 비용·속도 경향 (PR #56과 동일한 결론)

- nano가 가장 저렴·빠르지만 RQ042 등에서 다소 장황하고 조건부 안내가 많다.
- mini의 비용은 두 모델 사이이며, 품질 판단에는 위 표현 혼동도 함께 반영해야 한다.
- 5.4가 가장 느리고 비싸며(mini 대비 지연 2~3배, 비용 3~5배), 품질 차이는 이번 5문항에서는
  두드러지지 않았다.

## 이후 실행의 기록·예산 처리

- `comparison.jsonl`과 `comparison.csv`의 원본 응답·토큰·비용은 보존했다.
  위 표는 저장 결과의 사후 재검토이며, 과거에 없던 입력 기록을 소급 생성하지 않았다.
- 수정한 스크립트는 매 요청의 실제 검색 결과와 생성기에 전달한 Context·policy_checks·프로필을
  `input_trace`에 저장한다. SDK가 반환한 모델 원본 응답도 같은 trace에 저장한다.
  `run.json`에는 코드·질문 파일 해시, Git 상태, 데이터셋 버전과
  manifest 해시, 가격 가정, KST 실행 시각 및 완료·중단 상태를 기록한다.
- 모델마다 새 검색 세션을 쓰므로 기록된 지연은 검색·연결 준비·Checker·Generator를 포함한다.
  입력이 달라졌는지는 새 실행의 trace를 대조해야 한다.
- `--budget`은 **누적 추정 비용 기준으로 다음 요청을 중단하는 값**이다.
  마지막 요청으로 초과할 수 있으며 엄격한 청구액 상한을 보장하지 않는다.
  NaN·무한대·0·음수는 거부하고, API 호출 후 usage/비용이 미확인이면 그 결과를 남기고 중단한다.
  기록의 `known_cost_usd`는 확인된 비용의 합계다.
- 요청마다 결과 파일을 갱신하고, 실패·사용자 중단 시 확보한 결과와 실행 상태를 남긴다.
  비용이 확인된 오류 응답은 기록하고 비교를 계속하며, 전체 종료 시 `completed_with_errors`로 구분한다.
  비밀값을 마스킹한 기록에는 `redacted: true`를 표시한다.
- 결과 저장이 실패하면 `save_failed`, `results_consistent: false`를 기록한다.
  두 결과 파일의 교체가 부분적으로 끝났을 수 있으므로 완료 결과로 사용하지 않는다.
  쓰기 가능한 경우 `recovery.json`에 확보한 행을 보존한다. 디스크 전체 쓰기 실패 시에는
  복구 파일과 상태 기록도 보장할 수 없으며, 마지막으로 저장된 파일을 확인해야 한다.
