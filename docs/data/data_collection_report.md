## 3. 청킹 크기·Overlap·단위 실제 설정값 및 비교 분석

### 3.1 실제 적용된 청킹(Chunking) 설정값

| 구분 | 실제 설정값 및 규격 | 설명 및 근거 |
|---|---|---|
| **청킹 분할 단위** | **시맨틱 의미 섹션 (Semantic Section-based)** | 지원대상, 자격요건, 혜택내용, 신청방법, 제출서류 등 의미 완결형 섹션 기준 분할 |
| **청크 크기 (글자 수)** | **평균 610.0자 / 중앙값 749자** | Min: 82자, Max: 1,551자 (500~800자 구간 집중도: **68.9%**) |
| **Overlap (중복 구간)** | **100자 (PDF 장문 분할 시)** | 페이지 1,000자 초과 시 하단 분할 적용 (`text[:1000]`, `text[900:]`)으로 문맥 단절 방지 |
| **노이즈 필터링 기준** | **50자 미만 청크 즉시 폐기** | 공백, 헤더 단독 청크, UI 버튼 잡음(점자뷰어 등) 원천 차단 |
| **총 생성 청크 수** | **557건** | Qdrant Vector DB 적재용 (`data/handoff/qdrant/payload_chunks.jsonl`) |
| **Point ID 매핑** | **RFC 4122 표준 UUIDv5** | `uuid.uuid5(uuid.NAMESPACE_DNS, chunk_id)` 결정론적 1:1 고유 식별자 부여 |

### 3.2 서로 다른 청킹 전략의 비교 분석 (검색 성능 평가 가이드)

| 청킹 전략 | 설정값 및 방식 | 장점 | 단점 및 리스크 | 추천 적용 영역 |
|---|---|---|---|---|
| **전략 A: 고정 길이 (Fixed-size)** | 500자 단위, 100자 오버랩 | 구현 단순, 벡터 밀도 균일 | 문장 중간 절단 발생, 정책 자격 조건과 혜택이 분리되어 환각 유발 | 단순 FAQ 텍스트 |
| **전략 B: 시맨틱 섹션 (현재 채택)** | **600~900자, 의미 섹션 단위 분할** | **정책 요건-혜택의 문맥 완결성 보장, 검색 정확도(Hit@5) 극대화** | 공고문별 섹션 파싱 전처리 필요 (정제 완료) | **정부 지원 정책 및 공고문 RAG (최적)** |
| **전략 C: 문서 전체 (Document-level)** | 1,500~3,000자 통짜 청킹 | 전후 맥락 완전 보존 | 검색 임베딩 유사도 희석, LLM 컨텍스트 윈도우 낭비 | 1장짜리 초간단 안내문 |
