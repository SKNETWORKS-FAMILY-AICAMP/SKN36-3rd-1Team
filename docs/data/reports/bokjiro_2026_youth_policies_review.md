## 4. 넣지 않은 값

- 신청 주소(`official_apply_url`): XML에 신청 링크가 없어 `null`. 신청처는 `application_method`에 검수표 A의 원문 표현으로 적었다(예: "전국 고용센터에 신청(복지로 상세 기준, 온라인 신청 여부 확인 필요)").
- 신청기간: XML에 날짜·상시 문구가 없어 `미확인`. Checker 접수 상태는 `unknown`.
- 소득·가구 원문 확인(`income_source_review` 등): `not_reviewed`(기존 복지로 정책과 같음).

## 5. 나머지 정책 (인계만)

- `data/staging/bokjiro_2026/handoff/`에 361건 전체를 올렸다. 후보 데이터·DB에는 넣지 않는다.
  - `targets.jsonl`: 정책 기본 정보, 검수 판정, 원본 XML 해시, 본문 파일·해시, 기존 정책과 이름 중복 후보(7건)
  - `review_rows.jsonl`: 검수표 1,300행과 행별 판정(OK 1,284행)
  - `source_text/`: XML에서 만든 본문 361건
- 이어서 넣는 방법: `selection.json`에 정책을 추가 → `python scripts/stage_bokjiro_2026_policies.py` → `python scripts/build_incremental_release_candidate.py` → 건수 고정 테스트 갱신 → Neo4j·Qdrant 재적재(재임베딩).
  - 스크립트는 전 행 OK가 아니거나, 이름 중복 후보이거나, 조직 대상 의심(사유 없음)이면 멈춘다.
  - 넣기 전에 선별 기준(8.4 하드 게이트: 조직 전용·종료·내용 부족)을 팀이 정해야 한다.
