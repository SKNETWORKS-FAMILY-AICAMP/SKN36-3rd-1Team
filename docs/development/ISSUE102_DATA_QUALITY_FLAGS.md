# Issue #102 — v1.4.0 정적 데이터 품질 플래그 생성 및 적용

## 1. 작업 개요

- 관련 Issue: #102
- 작업 브랜치: `feature/102-v140-data-quality-flags`
- 기준 dev 커밋: `6b4fdc9`
- 검증 완료일: 2026-11-25
- 대상 데이터셋: `1.4.0-candidate` (R3D)

## 2. 문제 정의

기존 정적 품질 플래그는 v1.3.2 데이터셋을 대상으로 생성되었으며, v1.4.0 데이터셋에서는 적용되지 않았다.

기존 조사에서는 판정 보호 대상 100개 정책 중 63개는 그래프 기반 전체 보류가 적용되고 있었으나, 나머지 37개에는 필요한 정적 판정 보호가 적용되지 않는 문제가 확인되었다.

이후 정책 데이터 및 그래프 교정이 진행되었으므로 기존 플래그를 그대로 재사용하지 않고 최신 데이터셋을 대상으로 의미 점검을 다시 수행하였다.

## 3. 구현 내용

### 3.1. Neo4j 의미 점검 스크립트 복구 및 개선

- 기존 삭제된 의미 점검 스크립트 복구
- v1.4.0 릴리스 데이터 및 문서별 eligibility_attributes 활용
- 데이터셋 버전, manifest 및 정책 ID 검증
- 실제 R3D Neo4j 읽기 전용 조회
- 문서별 근거 및 출처 정보 유지
- 속성 부재와 제한 없음의 의미 구분
- AGE 조건 및 부정 조건 처리 보완

### 3.2. S10 혼인·자녀 조건 탐지 개선

혼인 또는 자녀 관련 그래프 조건이 존재한다는 이유만으로 전체 요건이 충분히 모델링되었다고 판단하지 않도록 탐지 규칙을 개선하였다.

측면별 분류:

- unmodeled: 관련 조건 미모델링 의심
- incomplete: 관련 조건은 있으나 세부 요건 누락 의심
- review: 추가 검토 필요
- consistent: 자동 점검 범위에서 일치
- no_text: 관련 원문 표현 미탐지

S10 규칙 식별자: `S10_v2_unmodeled_incomplete_review`

최초 점검 후보 83개에서 최종 100개로 증가하였다. 기존 후보는 제거되지 않았으며 17개 정책이 추가되었다.

### 3.3. 데이터셋 버전별 플래그 관리

- v1.4.0-candidate: 신규 v1.4.0 플래그 사용
- v1.3.2: 기존 레거시 플래그 유지
- 미지원 버전: not_applicable
- 데이터 및 플래그 버전 또는 manifest 불일치: stale
- 파일 미존재: missing
- 정상 검증 및 적용: applied

캐시 키에 데이터셋 경로, 버전, manifest 해시 및 플래그 파일 서명을 반영하였다.

신규 플래그 생성 시 보고서의 데이터셋 버전, manifest 및 S10 규칙을 검증하며, report_finding_index를 통해 보고서의 개별 근거를 추적할 수 있도록 하였다.

### 3.4. 기존 판정 시스템 연동

기존 서비스의 품질 평가 및 Checker 경로를 재사용하였다.

get_policy_graph_context → combine_policy_evidence → assess_policy_data_quality → check_eligibility

정적 플래그의 affected_attributes를 활용하여 영향을 받는 자격 판정을 확인 필요 상태로 보호한다.

품질 경고는 확정 오류 또는 부적격 판정이 아니다.

## 8. 한계 및 후속 개선 사항

- 자동 의미 점검 결과는 의심 후보이며 공식 원문 전수 검증을 수행하지 않았다.
- S10 정규식에는 오탐·미탐 가능성이 있다.
- POL_GOV_050에서 조례 명칭을 가구 유형 자격 요건으로 탐지한 오탐 근거가 확인되었다. 다른 미확인 요건의 존재 가능성 및 현재 Checker의 LTE 처리 한계를 고려하여 보수적인 보호를 유지하였다.
- 기존 Checker의 LTE 자녀 월령 자동 비교는 이번 작업 범위에 포함하지 않았다.
- 보호 누락 0개는 생성된 정적 플래그의 보호 범위 충족을 의미하며 정책 자격 판정 정확도 100%를 의미하지 않는다.
- 손상된 JSON의 예외 처리, 전체 플래그 스키마 검증, 원자적 파일 교체 및 레거시 파일 덮어쓰기 강제 차단은 후속 개선 가능 사항이다.
- 실제 Qdrant 검색, 임베딩, LLM 응답, API 및 UI를 포함하는 전체 E2E 테스트는 수행하지 않았다.
- 기존 test_final_v140_smoke.py의 정적 플래그 기대값은 갱신하였으나 해당 테스트 파일 전체는 실행하지 않았다.
- 실제 Neo4j 통합 검증은 읽기 전용 조회와 전후 건수 일치를 확인하였다. 전체 DB 내용의 재검증을 의미하지 않는다.

## 9. 결론

최신 v1.4.0 데이터셋에 맞는 정적 데이터 품질 플래그를 재생성하고 버전별 로딩 체계를 구현하였다.

최신 데이터 기준으로 필요한 보호가 누락된 40개 정책을 확인하였으며, 정적 플래그 적용 후 잔여 보호 누락 0개를 오프라인 검증과 실제 Neo4j 통합 검증에서 확인하였다.

기존 레거시 데이터셋 및 UNKNOWN 판정 안전성을 유지하면서 데이터셋 변경에 따른 정적 품질 보호 공백을 보완하였다.
