R3D 릴리스 파일을 지정해 다시 기동한 뒤 HTTP 200, 브라우저 전체 정책 249개를 확인했다. 연결한 manifest 파일 SHA-256은 `b31307223f7334ffb7588d55670318d07d36e3fc18a78f62e8c961fdad04f3da`이며 PR #119 기록과 일치한다. 목록 API는 릴리스 파일을 읽는다. [PR #119 검증 보고서](https://github.com/SKNETWORKS-FAMILY-AICAMP/SKN36-3rd-1Team/blob/8229620/docs/reports/issue107-r3d-verification.md)

## 재현 절차

1. 상담 행은 홈을 다시 열고 해당 질문과 가상 나이를 입력한 뒤 **질문하기**를 누른다. 연령은 표시된 값만 바꾸고 지역·소득·대화 이력을 비운다. 표의 **503**은 API 로그의 `SEARCH_BACKEND_UNAVAILABLE`과 UI의 “답변을 불러오지 못했어요”를 뜻한다.
2. 목록 행은 **정책 둘러보기 → 정책 검색**에 표기별로 입력한다. 결과 수와 카드명을 확인하고 펼친 카드의 관계 지도 링크에서 정책 ID를 확인한다. 출처 행은 **원문 보기**를 열어 실제 도착 페이지를 대조한다.

### 재연결 후 브라우저 재확인 (2026-11-25 KST)

| 환경·문항 | 관찰 결과 |
| --- | --- |
| 별도 상담 환경 `18217` / API `18200` · RQ040 | 답변이 공무원 지원 제외를 안내했다. 고용24 출처와 국민내일배움카드 1개가 표시됐다. 개인 조건 판정은 ‘추가 확인 필요’였다. |

별도 환경의 `/health`는 `ready: true`였으며, 위 두 문항에서 생성 답변을 확인했다. 해당 환경의 코드 커밋·검색 DB·실제 모델은 이번 재확인에서 식별하지 못했다. 기존 최신 dev 검증표의 차단 11건과 집계는 유지한다. 최신 dev에서는 RQ040의 오류만 다시 확인했고, 나머지 차단 시나리오는 재검증 대기다.

- K-패스 목록 누락은 UI 필터에서 최초 확인된다. `PolicyExplorer.tsx`의 검색은 정책명과 기관명을 소문자화하고 공백을 제거한 뒤 부분 문자열을 검사한다. 붙임표는 유지한다. 여섯 표기는 `data/metadata/data_corrections_v1.4.0.json`의 `search_alias_notes`를 기준으로 확정했다. 공백 유무 두 표기에서 같이 표시되는 유사 카드가 있어 후속 상담에서는 정책 ID별로 구분해 확인한다.
- #90 연령 근거는 사업안내서의 적용 연도·문서 연결과 출처 간 차이를 데이터 담당자가 확인한 뒤 같은 정책의 API 근거와 상담 카드까지 재검증한다. 세종은 정책 소개와 개별 모집의 문구를 확인한다.
- 상담은 최신 dev 서버에서 승인된 R3D 접속 설정을 확인한 뒤 재실행한다. #75는 검색 후보 → Checker 판정 → Generator 본문·인용 → API 응답 → 카드 순으로 대조한다. #79는 같은 프로필의 74·75·76세 및 무입력을 재검증한다. #103은 별칭 6개와 FAQ 적용 시점·환급률, 세종 상담을 확인한다. 공급자가 반환한 실제 모델 식별자와 검색 대상 DB도 확인 대상이다.
- 별도 검증으로 `tests/unit/test_faq_review_holds.py` 6건을 실행해 모두 통과했다. 이 테스트는 후보 릴리스와 청크의 표·기간·정책명을 검사한다. 전체 테스트·린트·빌드는 이번 범위에서 미실행했다.
