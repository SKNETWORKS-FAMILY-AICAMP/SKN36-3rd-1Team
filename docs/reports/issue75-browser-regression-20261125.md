## 재현 절차

1. 상담 행은 홈을 다시 열고 해당 질문과 가상 나이를 입력한 뒤 **질문하기**를 누른다. 연령은 표시된 값만 바꾸고 지역·소득·대화 이력을 비운다. 표의 **503**은 API 로그의 `SEARCH_BACKEND_UNAVAILABLE`과 UI의 “답변을 불러오지 못했어요”를 뜻한다.
2. 목록 행은 **정책 둘러보기 → 정책 검색**에 표기별로 입력한다. 결과 수와 카드명을 확인하고 펼친 카드의 관계 지도 링크에서 정책 ID를 확인한다. 출처 행은 **원문 보기**를 열어 실제 도착 페이지를 대조한다.

### 최신 dev 후속 검증 (2026-11-26 KST)

기준은 `f42e726cc5a8223179094359c2b20a422fe908a0` 및 이 브랜치의 제외 경고 표시 수정이다. FastAPI :18276, React :18278, R3D verify 대상 Qdrant :56756 및 Neo4j :56787을 사용했다. 로컬 릴리스 manifest는 `b31307223f7334ffb7588d55670318d07d36e3fc18a78f62e8c961fdad04f3da`다. DB 정상 조회 및 LLM 모델 실호출은 확인하지 못했다. 프로필은 모두 가상이다.

Edge에서 상담 입력란과 목록 화면이 로드됐고 FastAPI 로그에서 `GET /api/policies?limit=500&offset=0` HTTP 200을 확인했다. Edge 창의 입력 자동화가 차단되어 아래 질문은 직접 HTTP 요청으로 보냈다. 유효한 요청 10건 모두 FastAPI 로그와 응답에서 HTTP 503 `SEARCH_BACKEND_UNAVAILABLE`였다. 초기 422는 진단 요청에서 필수 프로필 필드를 빠뜨려 발생했고, 필드를 채운 재시도 결과가 아래 기록이다. 실행 환경에 R3D verify 전용 인증 설정이 없었으며 검색 실패의 상세 원인은 미확정이다.

### 기존 실패 재현 및 담당자 전달 사항
