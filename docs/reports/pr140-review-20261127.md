### 인용 번호·원본 문서 추적

1. 저장된 `hybrid[].result`의 각 hit에 policy/document/chunk ID·URL·rank가 있다.
2. Context Builder가 rank와 정책 균형에 따라 최대 5개를 선택하고 **그때의 source_id=1..N**을 부여한다. 검색 hit 순번과 같은 의미가 아니다.
3. Generator는 이 Context source_id를 `[n]`과 `used_source_ids`로 사용한다.
4. Pipeline의 상태 문장 보정은 일부 문장을 제거하거나 인용 사용 집합을 조정할 수 있다.
5. `_citations`는 실제 사용된 Context ID를 정렬한 뒤 **표시용 1..M으로 다시 번호를 매기고** citations 배열을 만든다.
6. FastAPI는 이 최종 answer와 배열을 응답한다. 원본 기록은 최종 응답만 저장했다.
7. 이전 재생 테스트는 표시용 `[1]`을 Context source_id 1로 되돌려 보내 정부24/공고 인용을 조례에 연결했다.
8. 수정된 모의 Generator는 **저장된 citations[n-1]의 문서 ID·URL·페이지**로 현재 Context를 찾아 번호를 변환한다. API 응답은 다시 어떤 표시 번호가 되더라도 각 문장 위치에서 같은 출처를 참조해야 한다. 번호 치환은 한 번의 정규식 변환으로 수행해 1↔2 교환이 연쇄 치환되지 않도록 했다.

정책 ID가 다르거나 정확한 원본 출처가 현재 Context에 없으면 번호/문서명으로 추정하지 않고 검증을 실패시킨다. 같은 문서·URL·페이지의 중복 인용은 서로 다른 Context source_id를 배정해 개수도 보존한다. 검색 순서 변경과 표시 번호 재배치 정상 사례를 확인했다.

**원래 chunk_id 미검증:** 저장된 실제 LLM 최종 API response의 Citation에는 chunk_id·retrieved_at·content_hash가 없다. 재생 Context의 chunk_id는 새 증거에 기록했지만 같은 문서/URL/페이지에 해당하는 여러 청크 중 원래 LLM이 어느 청크를 사용했는지는 복구할 수 없다. 이 경우 문서 단위 동등성만 검증했고 원래 청크를 임의 확정하지 않았다. 원래 page_number=null인 건도 null 일치이지 실제 공고 페이지 확인 완료가 아니다. API 계약은 변경하지 않았다.

### 독립 연령 기대값의 근거와 한계

`tests/fixtures/pr140_age_expectations.json`은 Checker 출력을 복사한 파일이 아니다. 교정 장부의 `COND_AGE_low_high` ID와 근거 문서/관계, 동결 조건 그룹을 검토한 정적 기준이다. 기존 승인 구조화 데이터의 비교 정확성을 검증하며 정책 원문의 미해결 불일치를 새로 판정하지 않는다.

- 53개 모두 신청자 `AGE`, 단위 `세`, 실제 연산자 `BETWEEN`이다. 노드 값·연산자·단위·정책별 근거 문서 관계·그룹 snapshot을 독립 fixture와 비교한다.
- 실제 상한이 있는 정책은 하한-1/하한/하한+1/상한-1/상한/상한+1과 미입력을 사용한다. 120은 무상한 sentinel이므로 실제 상한이나 121세 신청 경계로 만들지 않는다. -1은 Checker의 입력 범위 확인만 하고 API의 정상 입력으로 보내지 않는다.
- UNKNOWN 나머지 그룹이 있는 **46개**는 공개 age·종합 Checker·API가 needs_check라는 계약을 기대한다.
- 나머지 **7개**는 검증되지 않은 교육/취업/가구 등 다른 필수 조건으로 종합 결과가 needs_check이지만 개별 age는 범위 비교를 유지한다. 이 7개도 무조건 모든 조건 needs_check으로 만드는 것은 잘못이다. 실제 독립 기대값 도입 과정에서 이 차이를 확인해 분리했다.
- 개별 `_condition` 기대값, 공개 Checker의 age/마지막 eligibility 기대값, API age/마지막 eligibility 기대값을 모두 별도로 확인한다. Checker와 API가 함께 틀려도 동등성만으로 통과할 수 없다.

### 오류 감지 테스트

정상 인용, 표시 번호 재배치, 검색 순서 변경, 같은 정책의 서로 다른 문서와 실제 저장 7건을 확인했다. 같은 번호에 다른 문서 ID/URL/페이지를 주입하거나 문서 배열을 뒤집기, 다른 정책으로 교체하기, citation 누락, 페이지 필드 누락은 모두 assertion 실패/명시적 오류로 검출한다. `pytest.raises`는 이 거부 동작을 검증한다.

나이 하한 미만 eligible, 상한 초과 eligible, LTE→LT, GTE→GT, 미확인→eligible, 신청자/자녀 혼동, Checker와 API가 같은 잘못된 결과를 내는 7종을 독립 oracle로 거부한다. 추가로 실제 Checker `_condition`을 monkeypatch하여 이전 테스트가 놓쳤던 오류를 새 테스트가 감지하는지 확인했다. 주입은 테스트 프로세스/pytest fixture 안에서만 적용되며 서비스 파일에는 남지 않는다.
