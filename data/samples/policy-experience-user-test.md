# SSOK 사용자 테스트 준비안

상태: 준비 완료 / 실제 참여자 테스트는 아직 실시하지 않음.
화면은 dev 0118106 기반 API·프론트 변경본이다. 목록은 릴리스 파일 기반 실제 API로 연결했고, 실제 검색 DB·모델 평가는 별도다.

## 진행 방법

- 실제 나이·주소·소득 대신 아래 가상 조건을 제공한다. 이름·연락처·소득증빙을 수집하지 않는다.
- 참가자에게 정답 버튼 위치를 알려주지 않고, 막히는 지점과 이해한 내용을 관찰한다.
- 모델 호출이 필요한 본 서비스 평가는 별도 승인·환경 확인 후 진행한다. 모의 화면 테스트와 추천 정확도 평가는 구분한다.
- 정부 포털과 비교할 경우 같은 정책·같은 과제를 사용하고 사용 순서를 참가자별로 번갈아 배정한다.
- 시작은 과제 제시, 종료는 목표 도달 또는 참가자의 포기 선언이다. 공식 링크 클릭을 신청 완료로 기록하지 않는다.

## 과제

| 번호 | 가상 상황과 과제 | 관찰할 항목 |
| --- | --- | --- |
| T1 | 경기도 거주 25세 취업준비생. 주거 정책을 찾아 관심 목록에 저장한 후 새로고침해 다시 찾기 | 탐색 시간, 필터 이해, 저장·복원 성공 |
| T2 | 조건이 비어 있는 상담에서 나이 질문에 답하고 기존 질문의 조건이 갱신되는지 확인. 다시 질문이 나오면 나중에 입력 선택 | 재질문, 입력 취소, 질문 맥락 유지 |
| T3 | 공식 기준과 내 조건 결과가 다른 가상 카드를 보고 지금 신청 자격이 확정됐는지 설명하기 | 공식 기준/개인 판정 혼동, 보류 이해 |
| T4 | 정책 카드에서 신청 기관·필요 서류 확인 경로·공식 원문을 찾기 | 서류가 없는 것을 서류 불필요로 오해하는지, 링크 이해 |
| T5 | 확인된 오늘 마감 가상 정책의 캘린더 파일을 내려받고 저장 정책의 마감 안내 찾기 | D-day 이해, 자동 알림 보장 오해, 다운로드 성공 |
| T6 | 접수 마감·일정 미확인·출처 없는 카드를 각각 확인하기 | 접수 상태와 자격 혼동, 없는 신청 버튼 오해 |

추천 적합성은 공식 기대 근거·Checker 결과와 별도 평가한다. 화면 테스트 성공을 추천 정확도 통과로 합산하지 않는다.

## API 협의 항목

- 전체 정책 목록·데이터 버전 및 application_schedule: #107 로컬 계약안과 읽기 전용 API를 구현했다. 팀 검토와 실제 검색 DB 통합 검증은 남아 있다.
- 공식 요건: label/value/document_id/chunk_id/source_url로 명시된 원문 블록을 전달한다. 값·단위·연도 검수 완료를 의미하지 않으며, 출처를 대표 링크로 임의 대체하지 않는다.
- 필요 서류: required_documents 선택 필드에 원문 블록과 문서·청크·URL을 전달한다. 전체 서류 목록의 완전성은 보장하지 않으며, 없는 항목은 추정하지 않는다.
- 선택 정책 ID: AskRequest.selected_policy_id를 구현했고 재시도·프로필 갱신에서도 유지한다. 해당 정책 근거가 없으면 다른 정책으로 대체하지 않는다. 실제 검색 DB 어댑터 통합 확인은 별도다.
